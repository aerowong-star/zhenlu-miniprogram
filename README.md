# 诊路微信小程序（第一阶段）

本仓库是“罕见病复诊准备与病程整理助手”的第一阶段可审核版本。它采用原生微信小程序实现，当前不连接后端、不调用 AI，也不会上传任何数据。

## 本阶段已实现

- 首次使用说明与虚构示例病例
- 患者档案的新建、编辑、切换和删除
- 手动添加、编辑、查看和删除病程事件
- 按日期倒序展示病程时间线
- 按就诊、检查、用药、症状等分类筛选
- 本地数据清除和示例数据重置
- 诊疗边界与隐私提示

## 本阶段刻意不包含

- 微信正式登录、云数据库和多设备同步
- 报告上传、OCR 和 AI 结构化提取
- 指标趋势、复诊摘要和长图导出
- 诊断、病情判断、治疗或用药建议

这些内容属于第二、三阶段，第一阶段先保证在没有 AI 和后端的情况下，档案和病程主流程可以独立运行。

## 如何在微信开发者工具中运行

1. 安装并打开微信开发者工具。
2. 选择“导入项目”。
3. 项目目录选择本仓库根目录（包含 `project.config.json` 的目录）。
4. AppID 可先使用测试号；仓库中的 `project.config.json` 默认使用 `touristappid`。
5. 编译后从欢迎页选择“体验示例病例”或“创建自己的档案”。

本项目没有 npm 运行时依赖，不需要执行“构建 npm”。
## 本地数据说明

所有数据保存在微信小程序本地存储键 `zhenlu_phase1_state_v1` 中。旧版 `hanlu_phase1_state_v1` 数据会在首次启动时自动迁移。卸载小程序、清理微信缓存或在“设置”页面执行“清除全部本地数据”都会清除数据。

目前使用本地存储的原因：第一阶段无需申请云环境即可审查交互和数据模型。业务页面只调用 `miniprogram/services/data-service.js`，后续可以替换成云数据库实现。


## 审核建议流程

1. 首次打开，勾选体验说明并进入示例病例。
2. 在首页查看虚构患者和最近事件。
3. 在“病程”中切换筛选条件并打开事件详情。
4. 新建、编辑、删除一条病程事件。
5. 新建一份患者档案，并在“档案”页切换当前患者。
6. 在“设置”中查看数据概览，测试示例重载和本地清除。

## 运行检查

如果本机安装 Node.js，可在仓库根目录执行：

```powershell
npm test
npm run check
```

测试仅验证数据服务和日期工具，不会连接网络。

## 已知限制

- 数据仅保存在当前设备，不能跨设备同步。
- 暂未接入微信登录，因此没有真实用户身份。
- 目前日期按日记录，不支持同日事件的自定义排序。
- 设计需要在不同型号微信模拟器和真机上继续视觉验收。
