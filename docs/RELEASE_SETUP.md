# 第六阶段上线环境配置

本阶段新增版本化隐私同意、全量云端数据删除和服务端限流。以下配置都应在正式小程序当前使用的同一云环境中完成。

## 一、新增数据库集合

创建 `service_rate_limits`，权限设为“所有用户不可读写”，仅允许云函数服务端 SDK 访问。建议为以下字段创建单字段索引：

- `userHash`
- `expiresAt`

同时为已有 `ocr_rate_limits` 补充 `userHash` 和 `expiresAt` 单字段索引。新产生的 OCR 限流记录会写入这两个字段；旧记录不包含医疗内容。

## 二、新增云函数

右键 `cloudfunctions/manageMyCloudData`，选择“创建并部署：云端安装依赖（不上传 node_modules）”。函数超时建议保持 20 秒。

部署后用“设置 → 数据与隐私管理 → 查询云端数据”验证。返回值只能包含备份、邀请和授权数量，不应返回患者或病程内容。

## 三、重新部署已有云函数

以下函数加入了限流或限流记录清理，需要重新部署：

1. `manageUserBackup`
2. `manageCareSharing`
3. `recognizeMedicalReport`
4. `cleanupCareInvites`

确认 `cleanupCareInvitesDaily` 仍为启用状态。清理任务现在同时删除过期邀请码、OCR 限流记录和通用服务限流记录。

## 四、隐私政策上线阻断项

代码中的政策页面是结构模板。正式提交审核前必须根据真实运营情况补齐并核对：

- 小程序运营主体全称；
- 有效客服或隐私联系人渠道；
- 各类信息的实际保存期限；
- 百度 OCR 与微信云开发的实际服务和数据处理说明；
- 未成年人资料管理规则；
- 微信公众平台“用户隐私保护指引”所勾选的信息类型、用途和页面说明。

不得在上述信息仍为模板状态时宣称已完成法律合规。

## 五、费用与监控

- 为云函数调用次数、执行时间、数据库读写量和存储量设置费用预警；
- 每日检查发布初期的失败率和超时率，但日志不得输出医疗正文、邀请码、OpenID 或服务密钥；
- 限流集合必须保持客户端不可访问；
- 测试数据删除时优先使用虚构病例。
