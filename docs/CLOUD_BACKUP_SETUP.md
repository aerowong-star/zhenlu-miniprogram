# 个人云备份配置

第四阶段使用 `manageUserBackup` 云函数管理每位用户的一份个人备份。客户端不直接访问数据库，也不提交 OpenID；云函数从微信调用上下文获得身份，并用 SHA-256 摘要的前 128 位作为文档标识。

## 一、创建数据库集合

1. 在微信开发者工具中打开“云开发”。
2. 进入“数据库”，新建集合 `user_backups`。
3. 将集合权限设为“所有用户不可读写”或等价的自定义安全规则，使小程序端不能直接读写。
4. 不要在客户端代码中添加该集合的直接查询。

数据库只由云函数访问。每条文档包含 `schemaVersion`、`payload` 和 `updatedAt`；不保存明文 OpenID、百度密钥或报告原图。

## 二、部署云函数

1. 在资源管理器中右键 `cloudfunctions/manageUserBackup`。
2. 选择“创建并部署：云端安装依赖（不上传 node_modules）”。
3. 等待状态显示部署成功。
4. 在云开发控制台确认函数超时时间为 15 秒左右。

该函数不需要配置环境变量。云开发环境继续使用项目当前选中的环境，例如你已建立的 `cloud1`；代码通过动态当前环境运行，不依赖环境显示名称。

## 三、验证

1. 使用虚构示例数据进入“设置与说明”。
2. 点击“检查云备份”，首次应显示“暂无云端备份”。
3. 点击“立即备份”并确认，完成后应显示更新时间。
4. 修改一条本地记录，再点击“恢复到本机”，确认后应恢复为备份内容。
5. 点击“删除云端备份”，确认后重新检查，应显示“暂无云端备份”。

若提示找不到集合，先确认 `user_backups` 已在当前云环境创建。若提示找不到云函数，重新部署 `manageUserBackup`，并确认微信开发者工具当前选择的是同一云环境。

## 隐私与限制

- 备份只在用户明确点击并确认后上传；不会自动同步。
- 每个微信身份只保留一份云端备份，新备份会整体覆盖旧备份。
- 单份备份最大约 750 KiB，最多 20 个患者、5000 条事件和 500 个复诊计划。
- 清除本地数据不会自动删除云端备份；删除云端备份也不会清除本地数据。
- 当前版本没有照护者共享、公开链接、后台运营查看或数据导出接口。
