# 照护者协作配置

第五阶段通过 `manageCareSharing` 云函数建立微信身份之间的只读授权，并通过 `cleanupCareInvites` 定时删除未使用的过期邀请码。客户端不能直接访问协作数据库。

## 一、创建数据库集合

在当前云环境（例如 `cloud1`）创建：

- `care_invites`：尚未接受的一次性邀请；
- `care_grants`：已接受的只读授权。

两个集合的权限都设为“所有用户不可读写”或等价的自定义安全规则，只允许云函数通过服务端 SDK 访问。

如控制台提示查询缺少索引，请创建以下单字段索引：

- `care_invites.ownerHash`
- `care_invites.expiresAt`
- `care_grants.ownerHash`
- `care_grants.caregiverHash`

## 二、部署云函数

分别右键下面两个目录，选择“创建并部署：云端安装依赖（不上传 node_modules）”：

1. `cloudfunctions/manageCareSharing`
2. `cloudfunctions/cleanupCareInvites`

确认它们都部署到小程序当前使用的同一云环境。

## 三、设置过期邀请清理

在云开发控制台为 `cleanupCareInvites` 创建定时触发器，每天执行一次。建议在业务低峰期运行。该函数每次最多分批删除 1000 条已经超过 `expiresAt` 的邀请，不读取或修改仍在有效期内的邀请。

即使未配置定时触发器，管理者打开协作列表时也会清理自己名下的过期邀请；定时触发器用于保证长期不再登录用户的过期邀请也能删除。

## 四、双账号验证

1. 微信账号 A 使用虚构档案创建邀请码。
2. 通过可信私聊把邀请码交给微信账号 B。
3. 账号 B 输入邀请码并确认只读说明。
4. 账号 B 检查称呼和检验明细是否按 A 选择的范围显示。
5. 账号 A 更新共享内容，确认 B 重新进入后看到新快照。
6. 账号 B 测试“退出共享”；重新邀请后再由 A 测试“撤销授权”。

## 安全边界

- 邀请码由约 60 位随机熵生成，排除容易混淆的字符，最多 7 天有效且只能使用一次。
- 不保存明文 OpenID；数据库中只保存不可逆身份摘要。
- 不生成网页或公开访问链接。
- 照护者没有写入患者档案、病程、OCR 或复诊计划的接口。
- 撤销不能阻止对方在撤销前已经手工抄录或截图，因此只应邀请可信照护者。
