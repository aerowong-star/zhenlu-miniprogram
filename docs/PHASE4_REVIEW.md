# 第四阶段审核说明

本阶段交付的是个人云备份基础能力，不包含照护者共享。建议先用虚构数据验收，再决定是否进入共享授权设计。

## 自动检查

在仓库根目录执行：

```powershell
npm.cmd test
npm.cmd run check
```

## 本地数据迁移

1. 使用已有第三阶段数据启动小程序。
2. 确认患者、事件、OCR 核对结果和复诊计划仍然存在。
3. 确认设置页版本显示 `Phase 4 · v0.4.0`。

## 云备份验收

前置配置见 [CLOUD_BACKUP_SETUP.md](CLOUD_BACKUP_SETUP.md)。

1. 进入设置页，点击“检查云备份”，确认首次显示无备份。
2. 点击“立即备份”，检查上传内容说明，取消一次并确认未上传。
3. 再次点击并确认，检查状态和更新时间。
4. 修改本地记录后点击“覆盖备份”，确认覆盖提示正常。
5. 再修改一条本地记录，点击“恢复到本机”，确认警告明确说明会覆盖本机数据。
6. 恢复后检查患者、事件、复诊计划的关联均正确。
7. 点击“删除云端备份”，确认本地数据仍存在，重新检查后显示无备份。

## 安全检查

- `project.config.json` 使用 `touristappid`，仓库中不存在正式 AppID。
- 小程序代码中不存在百度 API Key、Secret Key 或 OpenID。
- 数据库 `user_backups` 禁止客户端直接读写。
- 云函数日志只记录操作类型和错误信息，不输出医疗内容。
- 备份中不包含报告原图；图片仍在 OCR 完成后按既有流程清理。

## 暂未包含

- 自动、实时或后台同步；
- 多份历史备份与版本冲突合并；
- 照护者邀请、撤销和权限分级；
- 运营后台读取医疗数据；
- 公开分享链接。
