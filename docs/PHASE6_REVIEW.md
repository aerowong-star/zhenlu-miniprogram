# 第六阶段审核说明

第六阶段目标是上线稳定性和数据权利闭环，不新增医疗判断功能。

## 自动检查

```powershell
npm.cmd test
npm.cmd run check
```

## 隐私同意

1. 清除 `zhenlu_privacy_consent_v1` 后冷启动，确认首先看到隐私说明。
2. 未勾选时“同意并继续”不可用。
3. 未同意时仍可打开隐私政策、用户协议和数据管理。
4. 同意后记录政策版本和时间；版本变化时必须重新同意。
5. 从设置撤回同意后不能继续进入业务页面。

## 云端数据权利

1. 使用虚构数据创建备份、待接受邀请和已接受授权。
2. 在数据管理页查询，只显示四类数量，不显示医疗内容。
3. 取消第一次删除确认，数据不变。
4. 完成两次确认后，重新查询四类数量均为零。
5. 确认本机数据仍存在；再单独清除本机数据。
6. 使用另一个微信身份确认被删除的共享授权已经不可访问。

## 错误与稳定性

1. 断网调用云功能，提示检查网络，不显示内部调用链。
2. 临时改用不存在的函数名，提示云函数尚未部署。
3. 人为制造超时，提示服务响应超时。
4. 连续点击提交按钮，不产生重复邀请、重复恢复或重复删除。
5. 高频调用超过限额后得到“操作过于频繁”，限流记录不含明文身份。

## 上线阻断项

- 产品内政策已替换为真实运营主体信息并完成专业复核；
- 微信公众平台隐私保护指引与代码行为一致；
- 所有业务集合和限流集合禁止客户端直接访问；
- `manageMyCloudData` 已部署并完成双账号删除测试；
- 正式 AppID和服务密钥不在 Git 仓库；
- 云函数日志不含病程正文、报告内容、邀请码和明文 OpenID；
- 费用预警、错误监控和回滚分支已准备。
