# 第一阶段审核说明

## 阶段目标

在不接入 AI、后端和真实微信身份的情况下，验证“患者档案 → 手动记录病程 → 时间线回顾”的基础产品闭环。

## 验收矩阵

| 编号 | 场景 | 预期结果 |
|---|---|---|
| P1-01 | 首次进入小程序 | 显示产品边界；未勾选说明时不能继续 |
| P1-02 | 进入示例病例 | 创建一份虚构患者档案和三条虚构事件 |
| P1-03 | 创建患者档案 | 患者称呼和病种必填，保存后成为当前档案 |
| P1-04 | 切换患者档案 | 首页和时间线同步切换到所选患者 |
| P1-05 | 编辑患者档案 | 修改后列表和首页展示最新内容 |
| P1-06 | 删除患者档案 | 同时删除该档案下的全部事件，并要求二次确认 |
| P1-07 | 新建病程事件 | 日期和标题必填，保存后出现在时间线 |
| P1-08 | 编辑病程事件 | 修改后详情页和时间线显示最新内容 |
| P1-09 | 删除病程事件 | 二次确认后从时间线删除 |
| P1-10 | 时间线筛选 | 可按就诊、检查、用药、症状和其他筛选 |
| P1-11 | 重载示例 | 只替换示例数据，不删除用户自己建立的档案 |
| P1-12 | 清除全部数据 | 二次确认后回到首次体验页 |

## 审核时重点观察

1. 首次使用者是否能理解这是“资料整理工具”而非“AI诊疗工具”。
2. 首页是否能让用户快速找到“记录病程”和“查看时间线”。
3. 患者档案字段是否足够，但不过度收集个人信息。
4. 事件类型是否符合罕见病患者实际记录习惯。
5. 时间线信息密度、字号、留白和操作入口是否舒适。
6. 删除档案和清除数据的风险提示是否足够明确。

## 当前待真机验证

- 微信开发者工具不同模拟器尺寸下的布局。
- iOS、Android 真机的字体、输入法和日期选择器表现。
- TabBar、返回栈及首次跳转的完整体验。
- 本地存储接近容量上限时的错误提示（本阶段没有图片数据，风险较低）。
