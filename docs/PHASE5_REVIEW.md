# 第五阶段审核说明

本阶段交付可撤销的照护者只读协作。正式验收需要两个不同的微信身份；单账号不能接受自己创建的邀请码。

## 自动检查

```powershell
npm.cmd test
npm.cmd run check
```

## 邀请与范围

1. 使用虚构示例档案进入“设置 → 照护者协作”。
2. 创建邀请码，确认患者称呼默认关闭、检验明细默认关闭。
3. 关闭病程记录，确认检验明细随之关闭且不能单独开启。
4. 检查邀请码按 `XXXX-XXXX-XXXX` 显示，并明确提示一次性和有效期。
5. 回到授权列表，确认可以取消尚未接受的邀请码。

## 双账号授权

1. 账号 A 创建邀请码，账号 B 接受。
2. 确认邀请码再次使用会失败，账号 A 不能接受自己的邀请码。
3. 账号 B 只能查看授权快照，没有编辑、删除或导入本地档案的入口。
4. 确认隐藏的称呼、检验明细没有出现在账号 B 页面。
5. 账号 A 更新本地内容后，账号 B 不会自动变化；A 点击“更新内容”后才变化。
6. 账号 B 主动退出后无法重新查看。
7. 重新邀请后由账号 A 撤销，账号 B 再次打开详情应提示授权不存在。

## 数据与权限

- `care_invites` 和 `care_grants` 禁止客户端直接读写。
- 云函数只从微信上下文获取身份，客户端请求中没有 OpenID。
- 邀请接受后删除 `care_invites` 文档；撤销或退出后删除 `care_grants` 文档。
- `cleanupCareInvites` 已配置每日定时触发器。
- 仓库使用 `touristappid`，不存在正式 AppID、API 密钥或报告原图。
