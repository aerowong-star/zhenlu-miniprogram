# 第二阶段审核说明

## 阶段目标

验证“选择检验报告图片 → OCR 结构化提取 → 用户逐项核对 → 保存为病程事件”的闭环。OCR 只负责转录，不解释指标，也不产生诊疗建议。

## 本阶段交付

- 检验报告图片拍摄或相册选择
- 上传前单次明确授权和设备端自适应图片优化
- 百度医疗检验报告单 OCR 云函数
- 离线虚构演示识别，不上传图片即可审核流程
- 报告基本信息与检验项目逐项编辑
- 强制人工核对确认后保存
- OCR 结果写入检查类病程事件并在详情页展示
- 第一阶段本地数据自动迁移到数据模型 v2
- 识别完成后临时云文件双重清理

## 验收矩阵

| 编号 | 场景 | 预期结果 |
|---|---|---|
| P2-01 | 未选择图片点击真实识别 | 提示先选择图片 |
| P2-02 | 未勾选上传授权点击真实识别 | 不上传并提示确认授权 |
| P2-03 | 选择体积或尺寸过大的图片 | 在设备端自动等比缩放和压缩，成功后才允许上传 |
| P2-04 | 点击演示识别 | 生成明确标记为虚构的报告和两项指标 |
| P2-05 | 修改任意识别字段 | “已核对”状态自动取消，必须重新确认 |
| P2-06 | 未确认人工核对时保存 | 保存按钮不可用 |
| P2-07 | 核对后保存 | 时间线新增一条“检查”事件 |
| P2-08 | 打开报告事件详情 | 展示项目、结果、单位、参考区间及原始提示 |
| P2-09 | OCR 服务失败 | 保留当前页面和图片，显示可理解的错误，不生成事件 |
| P2-10 | 打开第一阶段已有数据 | 患者与事件保留，自动迁移到模型 v2 |

## 审核路径

1. 从首页选择“识别检验报告”。
2. 先点击“体验演示识别”，检查校对和保存流程。
3. 修改一个项目结果，确认核对勾选会被取消。
4. 重新勾选并保存，在时间线打开事件详情。
5. 完成云函数配置后，再使用非敏感测试报告验证真实 OCR。

## 安全与医疗边界

- 小程序端、仓库和日志均不得保存百度 API Key 或 Secret Key。
- 报告图片只作为临时 OCR 输入，不写入本地病程记录。
- OCR 内容必须由用户对照原件确认，不能标记为“医学审核”。
- “结果提示”只保存报告上的原始符号，不把它转译为病情判断。
- 测试真实服务时应使用脱敏或专门制作的测试报告。

## 暂未包含

- 医疗报告长期云端存档
- 微信登录、跨设备同步和家庭共享
- 指标趋势图和跨报告对比
- AI 报告解读、诊断或用药建议
